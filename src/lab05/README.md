### JSON и конвертации: JSON ↔ CSV, CSV → XLSX

> **Цель работы:** изучить сериализацию и десериализацию JSON, преобразовать данные между JSON, CSV и XLSX, проверить структуру файлов и обработку ошибок.

**Условие:** [официальное ТЗ ЛР5](https://github.com/outtathe/python_bivt/blob/main/src/lab05/README.md). Оформление продолжает [ЛР4](../lab04/README.md) и порядок «задание → запуск → результат» из [примера преподавателя](https://github.com/outtathe/effective-broccoli/blob/main/README.md).

## Форматы и файлы

- **JSON** — текстовый формат объектов, списков и простых значений. Сохраняет типы: например, число `18` отличается от строки `"18"`.
- **CSV** — текстовая таблица с заголовком. В этой работе разделитель — запятая; значения при чтении остаются строками. Запятые, кавычки и переносы строк внутри полей обрабатывает модуль `csv`.
- **XLSX** — формат электронной книги Excel с листами, ячейками и настройками ширины столбцов.

## Задание A.1. JSON → CSV

**Функция:** `json_to_csv(json_path: str, csv_path: str) -> None` в [json_csv.py](json_csv.py).

Вход — непустой список словарей. Объединение всех ключей образует столбцы; **порядок столбцов — алфавитный**, через `sorted()`. Отсутствующее поле заполняется пустой строкой через `restval=""`.

**Вход — [people.json](../../data/samples/people.json):**

```json
[
  {"name": "Анна", "age": 18, "city": "Москва"},
  {"name": "Тимур", "age": 19, "city": "Избербаш"},
  {"name": "Мария, \"Маша\"", "age": 18, "city": "Санкт-Петербург"}
]
```

**Запуск и проверка заголовка и количества записей:**

```bash
python3.12 -m src.lab05.demo json-to-csv
```

Сценарий сравнивает число объектов JSON с числом записей CSV, проверяет алфавитный заголовок и печатает полученный файл.

**Результат — [people_from_json.csv](../../data/out/people_from_json.csv), 3 записи:**

```csv
age,city,name
18,Москва,Анна
19,Избербаш,Тимур
18,Санкт-Петербург,"Мария, ""Маша"""
```

**Допущения:** значения — строки, целые и конечные вещественные числа, `bool`. Числа записываются в текстовом виде, `bool` — как `True`/`False`. `null`, вложенные словари и списки отклоняются с `ValueError`, чтобы не превращать их в неоднозначный текст. Повторяющиеся или пустые ключи запрещены; список только из пустых словарей также отклоняется. Отдельный пустой словарь допустим, если столбцы есть в других объектах.

## Задание A.2. CSV → JSON

**Функция:** `csv_to_json(csv_path: str, json_path: str) -> None` в [json_csv.py](json_csv.py).

`csv.DictReader` связывает значения каждой записи с заголовками. Все значения сохраняются **строками**, включая возраст, ведущие нули и пустые поля. JSON записывается в UTF-8 с `ensure_ascii=False` и `indent=2`.

**Вход — [people.csv](../../data/samples/people.csv):**

```csv
name,age,city
Анна,18,Москва
Тимур,19,Избербаш
"Мария, ""Маша""",18,Санкт-Петербург
```

**Запуск и сравнение ключей, значений и количества объектов:**

```bash
python3.12 -m src.lab05.demo csv-to-json
```

**Результат — [people_from_csv.json](../../data/out/people_from_csv.json):** 3 объекта; ниже первый объект, остальные выводятся той же командой.

```json
[
  {
    "name": "Анна",
    "age": "18",
    "city": "Москва"
  }
]
```

**Граница обратимости:** CSV не хранит исходные типы JSON. Поэтому после JSON → CSV → JSON число `18` станет строкой `"18"`, а отсутствующее поле — `""`. Значения не угадываются и автоматически в числа не преобразуются.

## Задание B. CSV → XLSX

**Функция:** `csv_to_xlsx(csv_path: str, xlsx_path: str) -> None` в [csv_xlsx.py](csv_xlsx.py).

Программа переносит [people.csv](../../data/samples/people.csv) в настоящую книгу [people.xlsx](../../data/out/people.xlsx). Название единственного листа — **`Sheet1`**. Первая строка — заголовки, далее 3 записи. Все ячейки сохраняются как текст, чтобы не терять ведущие нули и не превращать значения вида `=1+1` или `#N/A` в формулы и ошибки Excel.

**Запуск с повторным открытием через `load_workbook()`:**

```bash
python3.12 -m src.lab05.demo csv-to-xlsx
```

Сценарий сравнивает каждую ячейку с исходным CSV, выводит листы, размеры таблицы и ширины. Пустые ячейки при повторном чтении могут возвращаться как `None`; при сравнении они приводятся к `""`.

**Фактически полученные параметры:**

| Параметр | Результат |
| :--- | :--- |
| Лист | `Sheet1` |
| Строк, включая заголовок | 4 |
| Столбцов | 3 |
| Ширина A / B / C | 15 / 8 / 17 |

Автоширина рассчитывается по максимальному `len()` содержимого столбца, включая заголовок: **`min(255, max(8, длина + 2))`**. Два символа дают запас; 8 — минимум по ТЗ, 255 — предел ширины Excel. Это расчёт по длине текста, а не измерение пикселей шрифта.

**Отдельная проверка файла одной командой Python:**

```bash
python3.12 -c 'from openpyxl import load_workbook; wb = load_workbook("data/out/people.xlsx"); ws = wb["Sheet1"]; print("Листы:", wb.sheetnames); print("Строк:", ws.max_row, "Столбцов:", ws.max_column); print("Ширины:", {c[0].column_letter: ws.column_dimensions[c[0].column_letter].width for c in ws.columns}); wb.close()'
```

**Открытие на MacBook для визуальной проверки в Excel, LibreOffice или Numbers:**

```bash
open data/out/people.xlsx
```

Дополнительный входной пример — [cities.csv](../../data/samples/cities.csv). Его можно проверить без создания лишнего файла в репозитории:

```bash
python3.12 -c 'from tempfile import TemporaryDirectory; from pathlib import Path; from openpyxl import load_workbook; from src.lab05.csv_xlsx import csv_to_xlsx; folder = TemporaryDirectory(dir="."); path = Path(folder.name) / "cities.xlsx"; csv_to_xlsx("data/samples/cities.csv", str(path)); wb = load_workbook(path); print(wb.sheetnames, list(wb.active.values)); wb.close(); folder.cleanup()'
```

## Проверки и обработка ошибок

```bash
python3.12 -m unittest src.lab05.test_lab05 -v
```

**Фактический результат проверки:** 12 тестов, `OK`, Python 3.12.14 и openpyxl 3.1.5. Проверены три преобразования, объединение ключей, строковые значения, кириллица, кавычки, запятые и переносы строк; граничные случаи, отсутствие stdout и возврат `None`; открытие XLSX, его содержимое, лист и автоширина.

Дополнительно `people.xlsx` успешно прочитан и пересохранён движком LibreOffice Calc в отдельную временную папку. После этого повторно проверены `Sheet1` и все значения — они совпали с исходным CSV. Файл в репозитории остаётся непосредственным результатом `csv_to_xlsx()`; ручная визуальная проверка на MacBook выполняется командой `open`, приведённой выше.

| Ситуация | Поведение |
| :--- | :--- |
| Входного файла нет | `FileNotFoundError` |
| Неверное расширение входа/выхода или каталог вместо входного файла | `ValueError` |
| Пустой, повреждённый JSON или неподдерживаемая структура | `ValueError` (включая `JSONDecodeError`) |
| Пустой CSV, пустые/повторяющиеся заголовки, разное число полей или повреждённые кавычки | `ValueError` |
| CSV только с корректным заголовком, даже без завершающего переноса строки | Допустим: JSON `[]`, XLSX только с заголовком |
| Неверная кодировка | `UnicodeDecodeError`, без подмены символов |
| Слишком большая таблица/ячейка или запрещённый управляющий символ для XLSX | `ValueError` |

CSV не содержит признака «это заголовок». **Первая запись всегда считается заголовком**; отсутствующий заголовок нельзя надёжно распознать по произвольным строкам без внешней схемы. Имена проверяются на непустоту и уникальность; пробелы в непустых именах и значениях сохраняются. Полностью пустые физические строки после заголовка `DictReader` пропускает; пустое поле внутри записи сохраняется. Автоопределение разделителя не используется.

Валидация входных данных выполняется до открытия выходного файла на запись; проверенные ошибки структуры не перезаписывают существующий результат. Ошибки доступа и записи передаются вызывающему коду. `demo.py` при ошибке сообщает о ней в stderr и завершает работу с кодом `1`.
